# Manta Globalization (i18n)

Manta provides a compile-time-safe, reactive multilingual system backed by YAML files and a Roslyn
source generator.

> **Note:** Only add multi-language YAML files when the user explicitly requests multi-language
> support. By default, a single `en.yml` (or whatever the base language is) is sufficient.

---

## 1. Project Structure

```
MyApp/
├── Langs/
│   ├── @config.yml      # Optional: generator config
│   ├── en.yml           # Base language (drives code generation)
│   └── zh_Hans.yml      # Additional languages
```

The `Langs/` folder must be inside the project that owns the strings. Each `.yml` file is an
**embedded resource** — set `Build Action: EmbeddedResource` (or `<EmbeddedResource>` in csproj).

---

## 2. YAML File Format

**en.yml (base language):**
```yaml
Title: Manta
Overview: Overview
SaveButton: Save
WelcomeUser: Hello, {0}!
```

**zh_Hans.yml:**
```yaml
Title: Manta
Overview: 概览
SaveButton: 保存
WelcomeUser: 你好，{0}！
```

- Simple flat key-value format (no nesting)
- Keys: PascalCase with underscores (e.g. `Dialog_Cancel`)
- Values: plain strings; `{0}` `{1}` … for format arguments

**@config.yml (optional):**
```yaml
base: en          # base language file (drives code generation, default: en)
comment: en       # language whose values appear in /// doc comments (default: en)
modifier: internal    # access modifier for generated class (default: public)
className: LangKey    # class name (default: LangKey)
```

## 3. Generated Code

After building, the Roslyn generator creates `Langs/LangKey.g.cs` (namespace: `{AssemblyName}.Langs`).
Doc comment values come from the `comment` language (default: `en`):

```csharp
// auto-generated from en.yml
namespace MyApp.Langs;

public static class LangKey
{
    /// <summary>Manta</summary>
    public const string Title = "MyApp_Title";

    /// <summary>Overview</summary>
    public const string Overview = "MyApp_Overview";

    /// <summary>Save</summary>
    public const string SaveButton = "MyApp_SaveButton";

    /// <summary>Hello, {0}!</summary>
    public const string WelcomeUser = "MyApp_WelcomeUser";
}
```

The actual stored key is `"{AssemblyName}_{YamlKey}"` — this namespaces keys from different
libraries so they never collide.

## 4. Registration (App Startup)

```csharp
// App.axaml.cs
protected override void OnInitialize(IServiceCollection services)
{
    Lang.Register(LangData.LoadFromAssembly(typeof(App).Assembly));

    // Restore saved language preference (optional)
    Lang.Current = configService.Config.Language;
}
```

`LangData.LoadFromAssembly()` discovers and loads all `Langs/*.yml` embedded resources.

## 5. AXAML Markup Extensions

All three extensions are in the global `https://github.com/avaloniaui` namespace — no extra
`xmlns` prefix needed.

### `{Lang}` — Translated string

```xml
<!-- Basic: generated constant as key -->
<TextBlock Text="{Lang {x:Static LangKey.Title}}" />

<!-- With format argument (replaces {0}) -->
<TextBlock Text="{Lang {x:Static LangKey.WelcomeUser}, {Binding UserName}}" />

<!-- Multiple format arguments Data1–Data5 -->
<TextBlock Text="{Lang {x:Static LangKey.Msg}, Data1={Binding A}, Data2={Binding B}}" />

<!-- Pin to a specific language regardless of Lang.Current -->
<TextBlock Text="{Lang {x:Static LangKey.Title}, LangType={x:Static LangType.ja}}" />

<!-- Fallback if key is missing -->
<TextBlock Text="{Lang {x:Static LangKey.Title}, DefValue='Untitled'}" />
```

`{Lang}` returns a `MultiBinding` — it automatically updates every bound element when
`Lang.Current` changes.

### `{LangEmoji}` — Flag emoji for a LangType value

```xml
<TextBlock Text="{LangEmoji {Binding}}" />   <!-- e.g. 🇺🇸, 🇨🇳, 🇯🇵 -->
```

### `{LangName}` — Native name of a LangType value

```xml
<TextBlock Text="{LangName {Binding}}" />    <!-- e.g. "English", "简体中文", "日本語" -->
```

## 6. ViewModel Usage

```csharp
using MyApp.Langs;
using Manta.Globalization;

[View<MyView>]
public sealed class MyView_Model : ViewModel
{
    // Use as a region/tab header — already a resolved key string, not a binding.
    // Because Lang extension in AXAML binds to Lang.Source.Current it still
    // updates automatically when language changes.
    public override string Header => LangKey.Overview;

    // Languages to show in selector
    public LangType[] Languages { get; } = [LangType.en, LangType.zh_Hans, LangType.ja];

    // Change language command
    public CommandWarper<LangType> ChangeLanguageCommand =>
        GetCommand<LangType>(lang =>
        {
            Lang.Current = lang;
            _config.Language = lang;   // persist (optional)
        });

    // Get translated string in code (non-reactive snapshot)
    public string GetGreeting(string name) =>
        Lang.Get(new LangGetOptions(LangKey.WelcomeUser, name));
}
```

## 7. Language Selector UI Pattern

```xml
<MItems ItemsSource="{Binding Languages}">
    <MItems.ItemTemplate>
        <DataTemplate x:DataType="LangType">
            <MButton Command="{Binding $parent[MView].DataContext.ChangeLanguageCommand}"
                     CommandParameter="{Binding}">
                <MPanel Mode="Horizontal" Spacing="6">
                    <TextBlock Text="{LangEmoji {Binding}}" />
                    <TextBlock Text="{LangName {Binding}}" />
                </MPanel>
            </MButton>
        </DataTemplate>
    </MItems.ItemTemplate>
</MItems>
```

## 8. LangType Enum

`LangType` is a Manta-defined enum with 40+ values, each decorated with metadata:

```csharp
public enum LangType
{
    en,        // 🇺🇸 English
    zh_Hans,   // 🇨🇳 简体中文
    zh_Hant,   // 🇹🇼 繁體中文
    ja,        // 🇯🇵 日本語
    ko,        // 🇰🇷 한국어
    fr,        // 🇫🇷 Français
    de,        // 🇩🇪 Deutsch
    es,        // 🇪🇸 Español
    // ... 30+ more
}
```

Extension methods: `langType.GetMetadata()` → `LangMetadata` (Emoji, EnglishName, NativeName)

## 9. Multi-Library Setup

Each library registers its own YAML bundle independently:

```csharp
// In the library's theme/init code
Lang.Register(LangData.LoadFromAssembly(typeof(MantaLibTheme).Assembly));
```

Generated keys are namespaced by assembly name, so `LangKey.Title` from `App` →
`"App_Title"` and `LangKey.Title` from `Lib` → `"Lib_Title"` — never collide.
