# Manta Globalization (i18n)

Manta provides a compile-time-safe, reactive multilingual system backed by YAML files and a Roslyn
source generator.

> **Note:** Only add multi-language YAML files when the user explicitly requests multi-language
> support. By default, a single `en.yml` (or whatever the base language is) is sufficient.

---

## 1. Project Structure

```
MyApp/
├── Langs/
│   ├── @config.yml      # Optional: generator config
│   ├── en.yml           # Base language (drives code generation)
│   └── zh_Hans.yml      # Additional languages
```

The `Langs/` folder must be inside the project that owns the strings. All `.yml` files are
automatically included as `AdditionalFiles` via `Generators.props`.

---

## 2. YAML File Format

**en.yml (base language):**
```yaml
Title: Manta
Overview: Overview
SaveButton: Save
WelcomeUser: Hello, {0}!
```

**zh_Hans.yml:**
```yaml
Title: Manta
Overview: 概览
SaveButton: 保存
WelcomeUser: 你好，{0}！
```

Rules:
- Simple flat key-value format (no nesting by default)
- Keys: PascalCase, underscores for grouping (e.g., `Dialog_Cancel`, `Demo_Style_Color`)
- Values: plain strings; `{0}`, `{1}`, … for format arguments
- Sequences become comma-joined: `Items: [a, b, c]` → `"a,b,c"`
- Hierarchical YAML is flattened with dot notation:

```yaml
SubGroup:
  Advanced: Advanced UI    # becomes key "SubGroup.Advanced"
  Base: Base UI            # becomes key "SubGroup.Base"
```

## 3. @config.yml (Optional)

```yaml
base: en              # Base language file (default: en)
comment: en           # Language for XML doc comments (default: en)
modifier: public      # Access modifier: public | internal (default: public)
classPrefix: ""       # Prefix for generated class names (default: "")
className: LangKey    # Class name (default: LangKey)
```

Example for a library (internal visibility):
```yaml
modifier: internal
classPrefix: Inner
```
→ Generates `InnerLangKey` (internal class) and `InnerLangData`

## 4. Generated Code

After building, the **LangGenerator** (Roslyn incremental generator) produces two classes:

### LangKey — Compile-Time Constants

```csharp
// auto-generated, namespace: {AssemblyName}.Langs
namespace MyApp.Langs;

public static class LangKey
{
    /// <summary>Manta</summary>
    public const string Title = "MyApp_Title";

    /// <summary>Overview</summary>
    public const string Overview = "MyApp_Overview";

    /// <summary>Save</summary>
    public const string SaveButton = "MyApp_SaveButton";

    /// <summary>Hello, {0}!</summary>
    public const string WelcomeUser = "MyApp_WelcomeUser";
}
```

Keys are namespaced as `"{AssemblyName}_{YamlKey}"` to prevent collisions across libraries.
Doc comments use values from the `comment` language.

### LangData — Runtime Dictionary

`LangData.LoadFromAssembly(Assembly)` discovers and loads all `Langs/*.yml` embedded resources
at runtime.

### Generator Diagnostics

| Code | Severity | Description |
|------|----------|-------------|
| `LANG001` | Error | Parsing error, invalid YAML, or missing base language file |
| `LANG002` | Warning | Missing translation key or redundant key in non-base language |

## 5. Registration (App Startup)

```csharp
// In App.axaml.cs OnInitialize
Lang.Register(LangData.LoadFromAssembly(typeof(App).Assembly));

// Restore saved language preference (optional)
Lang.Current = configService.Config.Language;
```

## 6. AXAML Markup Extensions

All three are in the global `https://github.com/avaloniaui` namespace — no extra prefix needed.

### {Lang} — Translated String

```xml
<!-- Basic: generated constant as key -->
<TextBlock Text="{Lang {x:Static LangKey.Title}}" />

<!-- With format argument (replaces {0}) -->
<TextBlock Text="{Lang {x:Static LangKey.WelcomeUser}, {Binding UserName}}" />

<!-- Multiple format arguments (Data1–Data5) -->
<TextBlock Text="{Lang {x:Static LangKey.Msg}, Data1={Binding A}, Data2={Binding B}}" />

<!-- Pin to a specific language regardless of Lang.Current -->
<TextBlock Text="{Lang {x:Static LangKey.Title}, LangType={x:Static LangType.ja}}" />

<!-- Fallback if key is missing -->
<TextBlock Text="{Lang {x:Static LangKey.Title}, DefValue='Untitled'}" />
```

`{Lang}` returns a `MultiBinding` that **automatically updates** every bound element when
`Lang.Current` changes.

### {LangEmoji} — Flag Emoji

```xml
<TextBlock Text="{LangEmoji {Binding}}" />   <!-- e.g. 🇺🇸, 🇨🇳, 🇯🇵 -->
```

### {LangName} — Native Language Name

```xml
<TextBlock Text="{LangName {Binding}}" />    <!-- e.g. "English", "简体中文", "日本語" -->
```

## 7. ViewModel Usage

```csharp
using MyApp.Langs;
using Manta.Globalization;

[View<MyView>]
public sealed partial class MyView_Model : ViewModel
{
    // As region/tab header — {Lang} in AXAML auto-updates when language changes
    public override string Header => LangKey.Overview;

    // Available languages for selector
    public LangType[] Languages { get; } = [LangType.en, LangType.zh_Hans, LangType.ja];

    // Change language command
    public CommandWarper<LangType> ChangeLanguageCommand =>
        GetCommand<LangType>(lang =>
        {
            Lang.Current = lang;
            _config.Language = lang;   // persist (optional)
        });

    // Get translated string in code (non-reactive snapshot)
    public string GetGreeting(string name) =>
        Lang.Get(new LangGetOptions(LangKey.WelcomeUser, name));
}
```

## 8. Language Selector UI Pattern

```xml
<MItems ItemsSource="{Binding Languages}">
    <MItems.ItemTemplate>
        <DataTemplate x:DataType="LangType">
            <MButton Command="{Binding $parent[MView].DataContext.ChangeLanguageCommand}"
                     CommandParameter="{Binding}">
                <MPanel Mode="Horizontal" Spacing="6">
                    <TextBlock Text="{LangEmoji {Binding}}" />
                    <TextBlock Text="{LangName {Binding}}" />
                </MPanel>
            </MButton>
        </DataTemplate>
    </MItems.ItemTemplate>
</MItems>
```

## 10. Multi-Library Setup

Each library registers its own YAML bundle independently:

```csharp
// In the library's initialization
Lang.Register(LangData.LoadFromAssembly(typeof(MyLibTheme).Assembly));
```

Generated keys are namespaced by assembly (`"App_Title"` vs `"Lib_Title"`), so they never collide.

Libraries can use `@config.yml` with `modifier: internal` and `classPrefix: Inner` to keep
generated types internal and avoid naming conflicts.
